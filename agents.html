Coding Agents#

ovspatialquery provides an agent skill: instructions, helpers, and complete programs that a coding agent such as Claude Code or Codex reads before it writes ovspatialquery code. The skill follows the open Agent Skills format, so any harness that reads that format can use it.

The skill covers what an agent otherwise finds by trial and error:

  • Loading a Universal Scene Description (USD) stage into ovstage and publishing the right version.

  • Choosing prims a population publishes, and reading the prims a publication left out.

  • Querying part of a stage with views, path scopes, and participation bits.

  • Converting USD time codes to the seconds ovstage expects.

  • Raycasts, sweeps, overlaps, and batched scans.

  • Pair discovery.

  • Explicit shapes.

  • C and C++ programs built with CMake against the SDK.

Install the Skill#

Before you begin, make sure you have the following:

  • A coding agent, such as Claude Code, Codex, or Cursor.

  • A copy of the skill: git to clone it from GitHub, or an installed ovspatialquery wheel or C SDK, which bundles it.

The skill is published in the NVIDIA-Omniverse/ovspatialquery GitHub repository under skills/ovspatialquery/. The C SDK includes the same folder under share/ovspatialquery/skills/ovspatialquery/, and the Python wheel installs it inside the package as ovspatialquery/skills/ovspatialquery/.

Copy the folder to where your harness looks for skills. The following table lists the folders:

Harness

One Project

Every Project

.agents/skills/ovspatialquery/

~/.codex/skills/ovspatialquery/

Refer to the harness documentation

For a skill that matches your installed SDK or wheel, copy the bundled folder instead of the development skill. The following commands install the development skill from GitHub for every project, on Linux or macOS:

git clone --depth 1 https://github.com/NVIDIA-Omniverse/ovspatialquery.git ovspatialquery-src
mkdir -p ~/.claude/skills ~/.codex/skills
cp -r ovspatialquery-src/skills/ovspatialquery ~/.claude/skills/
cp -r ovspatialquery-src/skills/ovspatialquery ~/.codex/skills/

The following commands do the same on Windows in PowerShell:

git clone --depth 1 https://github.com/NVIDIA-Omniverse/ovspatialquery.git ovspatialquery-src
New-Item -ItemType Directory -Force "$HOME\.claude\skills", "$HOME\.codex\skills" | Out-Null
Copy-Item -Recurse ovspatialquery-src\skills\ovspatialquery "$HOME\.claude\skills\"
Copy-Item -Recurse ovspatialquery-src\skills\ovspatialquery "$HOME\.codex\skills\"

To install the copy that matches an installed wheel instead, print its folder and copy that:

python -c "import ovspatialquery, pathlib; print(pathlib.Path(ovspatialquery.__file__).parent / 'skills' / 'ovspatialquery')"

Start a new session after you copy the skill, so the harness finds it. To check that it did, ask the agent which skills it can use, and look for ovspatialquery in the answer.

Tip

A harness without skill support can still use the skill. Tell the agent to read ovspatialquery/SKILL.md, for example from your project’s AGENTS.md.

Skill Contents#

The skill has the following parts:

Part

Purpose

SKILL.md

When to use the skill, the rules that prevent silent mistakes, and which program to start from.

scripts/ovsq.py

A small Python helper for stage loading, version and time bookkeeping, prim selection, and batched raycasts.

assets/python/, assets/native/

Complete programs for each task family, in Python, C, and C++, that check their own answers.

references/

One page per topic, plus a table from error messages to their causes.

evals/

The evaluation tasks the skill was measured with. Agents do not read them.

skill-card.md, BENCHMARK.md

What the skill is for, its known risks, and how agents scored with and without it.

skill.oms.sig

NVIDIA’s signature over every file in the folder except Git files.

Verify the Skill#

To confirm that a copy of the skill is the one NVIDIA signed, check skill.oms.sig against NVIDIA’s agent-skill certificate. Copy the whole folder, including evals/, because verification fails when a skill file was added, removed, or changed after signing. Git files (.git, .github, .gitignore, and .gitattributes) are not signed and do not affect the result.

Before you begin, make sure you have Python and curl. Then run the following commands, which were checked with model-signing 1.1:

pip install model-signing pyopenssl
curl -L -o nv-agent-root-cert.pem \
  https://raw.githubusercontent.com/NVIDIA/skills/main/nv-agent-root-cert.pem
model_signing verify certificate <path>/ovspatialquery \
  --signature <path>/ovspatialquery/skill.oms.sig \
  --certificate_chain nv-agent-root-cert.pem

The last command prints Verification succeeded for an unchanged copy. A copy whose skill files you edited is no longer the signed skill, so verify before you make local changes.
