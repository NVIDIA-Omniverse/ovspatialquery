Troubleshooting#

This page lists the failures that a first installation or a first program most often meets. Each section quotes the message you see, says what causes it, and gives the fix.

The Wheel Does Not Install#

pip install ovspatialquery finds no wheel for the host:

ERROR: Could not find a version that satisfies the requirement ovspatialquery (from versions: none)
ERROR: No matching distribution found for ovspatialquery

Installing a downloaded wheel file fails the same way with this message:

ERROR: ovspatialquery-<version>-py3-none-<platform>.whl is not a supported wheel on this platform.

No wheel’s platform tag matches the host, or the Python version is not supported. Each release provides a wheel for each of the following platforms:

Platform

Wheel Tag

Linux x86-64 (glibc 2.35 or newer)

manylinux_2_35_x86_64

Linux AArch64 (glibc 2.35 or newer)

manylinux_2_35_aarch64

Windows x86-64

win_amd64

Use one of these platforms. On Linux, ldd --version prints the glibc version; pip refuses these wheels on a release older than 2.35. The Python version must be 3.11, 3.12, or 3.13.

The Library Does Not Load#

Library.open() raises LibraryLoadError with the path it tried, as in this example:

ovspatialquery.library.LibraryLoadError: OVSPATIALQUERY_LIBRARY ovspatialquery library does not exist: /opt/sdk/lib/libovspatialquery.so

The first word names where the path came from, in the order in which Library.open() looks:

  1. explicit: the path passed to Library.open(path).

  2. OVSPATIALQUERY_LIBRARY: the environment variable.

  3. bundled wheel artifact: the copy inside the wheel.

Correct or unset the path that the message names. A message that starts with Failed to load the complete core interface means that the file exists but is not a complete build of this library for this platform. A message that starts with Unsupported ovspatialquery interface version means that the file comes from another minor release than the Python package. Use the library from the same release as the package. Refer to Install for the check that prints the loaded version and path.

CMake Cannot Find the SDK#

find_package(ovspatialquery CONFIG REQUIRED) fails with this message:

Could not find a package configuration file provided by "ovspatialquery"

CMake does not know where the SDK is. Pass the directory that holds the unpacked SDK’s include/ and lib/ folders as -DCMAKE_PREFIX_PATH=<sdk-root>. With COMPONENTS ovstage, add ovstage’s CMake package directory to the same list, separated by a semicolon. Refer to C and C++ SDK.

The ovstage Version Is Refused#

instance.ovstage(ovstage, stage) raises an error that names the version it found:

Ovstage companion requires a supported release (0.3.x, 0.4.x); observed '0.2.1'

The installed ovstage release is not supported. Install a supported release:

Requirement

Supported Versions

ovstage

0.3, 0.4

CUDA Is Unavailable#

Creating a plan on a CUDA device fails with NOT_SUPPORTED. The error detail starts with CUDA is unavailable: and names the cause. CUDA work never falls back to the CPU. The following messages are the most common:

  1. the NVIDIA driver library (libcuda.so.1 or nvcuda.dll) could not be loaded: no NVIDIA driver is installed, or the process cannot see it. Install the driver, or run the work on the CPU.

  2. the NVIDIA driver is too old for the bundled ovspatialquery_cuda.ptx: update the driver to one of the versions in the following table.

  3. the bundled ovspatialquery_cuda.ptx needs a GPU of compute capability 7.5 or newer: the GPU is older than Turing. Run the work on the CPU.

  4. the NVIDIA driver reports no CUDA device with the requested ID: the device ID is outside the devices that the driver reports.

CUDA work has these minimums:

Requirement

Minimum

GPU compute capability

7.5 (Turing)

CUDA driver version

12.8 (R570)

NVIDIA driver on Linux

570.26

NVIDIA driver on Windows

570.65

A plan on a CUDA device also needs a device budget. Without one, creating it fails with DEVICE_BUDGET. Refer to CUDA Devices.

A Prim or a Shape Is Refused#

An ovstage publication succeeds without the prims it cannot publish exactly and lists each one with a reason, such as UNSUPPORTED_TYPE or MALFORMED_GEOMETRY. Refer to Excluded Prims for every reason.

An explicit registration instead fails with INVALID_ARGUMENT, and the detail names the definition. A convex definition is refused when its hull exceeds 255 vertices or 254 faces, or when its points lie too nearly in one plane. Refer to Convex Hulls for the limits and the alternatives.

Other Errors#

Every C call returns a status, and the Python package raises ApiError with that status and a description of the failure. Refer to Status Codes for what each status means.
