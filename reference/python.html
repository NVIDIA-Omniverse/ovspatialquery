Python Package#

The ovspatialquery package calls the C library through ctypes. Each method that wraps a C function names it. The C reference states that function’s full contract, and a failed call raises ApiError carrying the C status. Importing the package does not load the native library. Library.open() loads it.

class ovspatialquery.Instance(
library: Any,
handle: int,
keepalive: Iterable[Any] = (),
)#

Owns every object created through it. Closing it, or leaving its block, closes what is still open: operations (waiting for pending ones), plans and reporters (waiting for slots retired with close_after_cuda), views, populations, then geometry definitions, each newest first, and then destroys the instance. On a normal exit a failure raises. When the block raises, each failure is added to that exception as a note instead. Either way, an instance that is not destroyed is kept, with what it still owns, until a later close succeeds or the process exits.

Captures and prepares immutable convex definitions. The five face columns describe source topology and come all together or not at all.

Both options apply to every definition in the call. hull_vertex_limit zero registers each definition’s own hull; 8 to 64 registers the hull PhysX cooks for a convexHull collider under that limit, whose corners need not be points and which may leave points outside. That hull is cooked from the vertices as given and placed afterwards by each instance’s pose and uniform_scales, as the simulation places a collider: register a stage’s collider from its local points in stage units and place it with the prim’s rotation, and its translation and uniform scale times the stage’s meters per unit, because vertices with the placement already applied can give another hull. enclosure_tolerance is how far outside the own hull, as a fraction of the largest half extent of the points’ box, a point may lie and still count as enclosed: zero is 2^-20, other values lie from 2^-20 to 2^-16.

class ovspatialquery.ExplicitPopulation(
adapter: ExplicitAdapter,
handle: int,
)#

Publishes instance rows from DLPack columns named as in ovspatialquery_explicit_instance_table_t, all on one device. CPU columns are captured on the host. CUDA columns require cuda_stream, which is forwarded to each column’s __dlpack__ and orders the library’s reads after the writes queued on it; an optional cuda_wait_event, recorded once the columns are written, also orders writes from other streams. The library prepares the version as preparation says; ON_DEVICE and ON_DEVICE_HOST_READABLE are experimental and may change in any minor release. Without copy, the returned operation borrows each column until it is closed, and the caller must not write to it before then. With copy, the library queues its copy of CUDA columns on cuda_stream before returning, so a write from another stream must wait for an event the caller records there afterwards.
